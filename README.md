# MDV Map Viewer — clone

A faithful rebuild of the cadastral/address map at `raajje.app/map/`, on a modern
stack: **Next.js 16**, **TanStack Query**, **shadcn/ui + Tailwind v4**, and a
spatial database (**MySQL 8** by default, **PostgreSQL + PostGIS** optional).

The map renders the full national dataset — parcels, house parcels, plot lines,
addresses, islands, atolls, airports and capitals — served as GeoJSON through an
API that is wire-compatible with the original `layers.php`.

## What was scraped

A recursive **quadtree crawler** (`scripts/scrape.mjs`) works around the upstream
1000-features-per-request cap by subdividing any saturated tile. One full national
crawl produced:

| Layer | Features | Served |
| --- | ---: | --- |
| addresses | 92,465 | tiled (zoom 18+) |
| plot_lines | 90,184 | tiled (zoom 17+) |
| house_parcels | 46,915 | tiled (zoom 17+) |
| parcels | 11,323 | tiled (zoom 16+) |
| island_names | 1,187 | static |
| atoll_boundaries / administrative_atolls / airports / atoll_capitals | 83 | static |

Data lands in `_scrape/data/*.ndjson` (one GeoJSON feature per line).

### A note on the residents directory

The original site also exposes `search-residents.php`, a **live national ID
register** — real names, ID numbers, dates of birth and home addresses. That data
is **not** scraped or reproduced here. The search box is instead backed by
**synthetic records** generated by `scripts/seed-residents.ts` (IDs prefixed
`SYN-`), so the search UI and API contract work end-to-end without exposing any
real personal data.

## Quick start

```bash
npm install
cp .env.example .env.local        # defaults to MySQL on localhost:3306
```

### 1. Get a database

**Option A — Docker (clean, known credentials):**

```bash
docker compose --profile mysql up -d       # or: --profile postgres
```

**Option B — an existing MySQL 8 server:** create the database and user, then
point `DATABASE_URL` at it:

```sql
CREATE DATABASE mdv_map CHARACTER SET utf8mb4;
CREATE USER 'mdv'@'%' IDENTIFIED BY 'mdv';
GRANT ALL PRIVILEGES ON mdv_map.* TO 'mdv'@'%';
FLUSH PRIVILEGES;
```

### 2. Migrate, import, seed

```bash
npm run db:migrate      # apply the schema for the configured dialect
npm run db:import       # load _scrape/data/*.ndjson  (~240k features)
npm run db:seed         # generate 25k synthetic residents
# or all three:
npm run db:setup
npm run db:stats        # row counts per table
```

### 3. Run

```bash
npm run dev             # http://localhost:3000
```

## Switching to PostgreSQL

Set two variables in `.env.local` and re-run the setup — the schema, importer,
seeder and API all switch dialect from this single flag:

```env
DB_DIALECT=postgres
DATABASE_URL=postgresql://mdv:mdv@127.0.0.1:5432/mdv_map
```

PostgreSQL requires the **PostGIS** extension (the `postgis/postgis` Docker image
ships it; the migration runs `CREATE EXTENSION IF NOT EXISTS postgis`).

## How the spatial layer works

Everything dialect-specific lives in `src/lib/dialect.ts`:

- **MySQL** stores geometry as `SRID 0` in `(lon, lat)` order and filters with
  `MBRIntersects` against a WKT envelope — an index-only bounding-box test.
- **PostGIS** stores true `SRID 4326` and filters with the `&&` operator against
  `ST_MakeEnvelope`, served by a GIST index.

Both back the same `/api/layers?layer=&bbox=` endpoint, which reassembles rows
into the exact GeoJSON property shape the original emitted (mapping defined once
in `src/lib/layers.ts`).

## Re-scraping

```bash
npm run scrape                          # all layers
node scripts/scrape.mjs parcels         # one layer
node scripts/scrape.mjs --reset         # discard resume state and start over
```

The crawl is resumable: progress is checkpointed to `_scrape/data/<layer>.state.json`,
so an interrupted run continues from its pending tile queue.
